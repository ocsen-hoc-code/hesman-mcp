**Hesman** — это MCP-сервер (Model Context Protocol) нового поколения, который предоставляет AI-агентам глубокое понимание вашей кодовой базы: символы, графы вызовов, зависимости и семантический поиск — с трёхуровневым конвейером сжатия, который радикально сокращает потребление токенов (до 97% в лучшем случае). Всё работает локально. Никаких внешних API. Никаких LSP-серверов.

## Зачем Hesman?

AI-агенты для кодинга мощны, но дороги. Каждая строка кода, которую они читают, стоит токенов. Отправлять целый файл, когда агенту нужна всего одна функция, — впустую тратить контекст и деньги.

Hesman решает эту проблему следующим образом:

- **Отдаёт только то, что нужно агенту** — конкретную функцию, её вызывающие, вызываемые ей или символы, затронутые изменениями.
- **Сжимает каждый ответ** — трёхуровневый конвейер удаляет комментарии, обрезает нерелевантный код и суммирует большие наборы результатов.
- **Заменяет сырые списки сводками** — вместо 200 ссылок в JSON-массиве агент получает блок `_summary` с количеством по типу и файлу.
- **Работает на 100% локально** — никаких API-ключей, сетевых вызовов или задержек от внешних сервисов. Ваш код никогда не покидает вашу машину.
- **Измеримая экономия** — каждый ответ содержит `_meta.reduction`, показывающий, сколько токенов сэкономлено по сравнению с сырым выводом.

Результат: агенты работают быстрее, стоят дешевле и рассуждают точнее, потому что видят нужный код, а не весь код.

## Быстрый старт

```bash
# 1. Установить глобально
npm install -g hesman-mcp

# 2. Запустить сервер внутри вашего проекта
cd my-project
hesman

# 3. Зарегистрировать в вашем AI-агенте (Claude Desktop, Cursor, VS Code)
hesman install --agent claude
```

Вот и всё. После завершения начальной индексации (несколько секунд для большинства проектов) ваш AI-агент сможет опрашивать кодовую базу через 11 инструментов Hesman.

## Возможности

### Интеллектуальный анализ кода

| Возможность | Описание |
|---|---|
| **Поиск символов** | Поиск функций, классов, методов по имени — точный, нечёткий или по префиксу (< 1 мс) |
| **Обход графа вызовов** | Обход вызывающих и вызываемых функций до 3 уровней глубины |
| **Отслеживание ссылок** | Поиск всех использований символа в кодовой базе |
| **Анализ влияния** | Что сломается, если переименовать, удалить или изменить сигнатуру символа |
| **Семантический поиск** | Опишите на естественном языке, что ищете, и найдите подходящий код |
| **Структурный поиск** | Поиск паттернов кода, таких как `console.$METHOD($$$ARGS)`, с именованными захватами |
| **Анализ зависимостей** | Просмотр того, что импортирует файл и что импортирует его |
| **Контекстные окна** | Сфокусированный компактный код вокруг любого места в файле |

### Конвейер сокращения токенов

Трёхуровневый конвейер сжатия Hesman сокращает использование токенов в каждом ответе. Фактическая экономия измеряется и сообщается через `_meta.reduction` в каждом ответе.

| Уровень | Техника | Типичная экономия | Лучший случай |
|---|---|---|---|
| **Компактный режим** | Удаляет комментарии, пустые строки, конечные пробелы; убирает неиспользуемые импорты | 10–30% | ~35% (сильно закомментированный код) |
| **Обрезка контекста** | Оставляет только строки, релевантные искомому символу; заменяет пропущенный код маркерами количества | 50–80% (поверх компактного) | ~95% (большие файлы с малой областью фокуса) |
| **Умная сводка** | Заменяет большие массивы результатов агрегированными блоками `_summary`; сжимает цепочки вызовов в сгруппированную статистику | 70–90% (для инструментов со списками) | ~90% (500+ ссылок -> сводка) |

**Совокупный лучший случай:** Файл из 430 строк, запрошенный через `get_context` для одной функции -> обрезан до ~6 релевантных строк + компактный режим -> **до 97% сокращения**. Это идеальный сценарий; типичное использование по всем инструментам даёт сокращение в среднем 20–70%.

### Готов к продакшену

- **Пул воркеров** — параллельная индексация на всех ядрах CPU, автоматический размер по умолчанию
- **Отслеживание файлов** — инкрементальная переиндексация при изменениях файлов через chokidar
- **Корректное завершение** — завершает активные задачи, сохраняет хранилища, корректно останавливает воркеры
- **Индексация по хешу содержимого** — файлы переразбираются только при фактическом изменении содержимого
- **Поддержка монорепозиториев** — автоопределение pnpm, lerna, nx, turbo и npm workspaces
- **Диагностика** — `hesman diag` выводит информацию о памяти, состоянии хранилищ, пуле и кеше
- **Протестирован в CI** — запускается на Ubuntu, macOS и Windows с Node 20 и 22

## Как работает сокращение токенов

### Уровень 1: Компактный режим

Удаляет комментарии, пустые строки и конечные пробелы, сохраняя магические комментарии (`// @ts-ignore`, `// eslint-disable-*`). Уровень 2 добавляет AST-обработку JSDoc и удаление неиспользуемых импортов.

До:
```typescript
// This function calculates the total price
// including tax and shipping
function calculateTotal(
  items: CartItem[],      // shopping cart items
  taxRate: number,        // local tax rate
): number {
  let total = 0;

  // Sum up item prices
  for (const item of items) {
    total += item.price * item.quantity;
  }

  // Apply tax
  total = total * (1 + taxRate);

  return total;
}
```

После (Уровень 1):
```typescript
function calculateTotal(
  items: CartItem[],
  taxRate: number,
): number {
  let total = 0;
  for (const item of items) {
    total += item.price * item.quantity;
  }
  total = total * (1 + taxRate);
  return total;
}
```

После (Уровень 2 — AST-aware, сохраняет только JSDoc):
```typescript
/**
 * Calculates the total price including tax.
 * @param items - Shopping cart items
 * @param taxRate - Local tax rate as decimal (e.g., 0.08)
 */
function calculateTotal(items: CartItem[], taxRate: number): number {
  let total = 0;
  for (const item of items) {
    total += item.price * item.quantity;
  }
  total = total * (1 + taxRate);
  return total;
}
```

### Уровень 2: Обрезка контекста

Когда агент запрашивает `get_context` для конкретного символа, Hesman возвращает только релевантный код:

```typescript
// ... (45 lines omitted: unrelated imports and helper functions)

/**
 * Processes the incoming webhook payload.
 */
export async function handleWebhook(payload: WebhookPayload): Promise<Result> {
  // ... (function body)
}

// ... (120 lines omitted: unrelated class definitions)
```

Обрезка сохраняет: определение целевого символа, его документационный комментарий, прямых вызывающих и вызываемых в пределах того же файла, а также внутрифайловые ссылки — всё остальное заменяется маркером количества.

### Уровень 3: Умная сводка

Вместо того чтобы выгружать 200 ссылок в JSON-массиве:

```json
{
  "_summary": {
    "totalCount": 200,
    "byKind": { "calls": 145, "imports": 38, "extends": 12, "type_ref": 5 },
    "byFile": [
      { "filePath": "src/services/payment.ts", "count": 34 },
      { "filePath": "src/controllers/checkout.ts", "count": 28 }
    ]
  }
}
```

Агент может затем запросить детали для конкретных файлов или типов — с пагинацией через `cursor`.

### Измерение экономии

Каждый ответ Hesman содержит блок `_meta` с фактической экономией токенов:

```json
{
  "_meta": {
    "originalTokens": 2007,
    "compressedTokens": 58,
    "reduction": "97.1%",
    "layers": ["compact", "prune"]
  }
}
```

Это позволяет точно оценить, сколько Hesman экономит в ваших реальных задачах.

## Установка и настройка

### Предварительные требования

- **Node.js** ≥ 20.0.0
- **npm** (или pnpm / yarn)

### Установка из npm

```bash
npm install -g hesman-mcp
```

### Установка из исходного кода

```bash
git clone https://github.com/ocsen-hoc-code/hesman-mcp.git
cd hesman-mcp
npm install
npm run download:parsers   # Загрузка WASM-парсеров Tree-sitter
npm run build              # Компиляция TypeScript
npm link                   # Сделать `hesman` доступным глобально
```

### Регистрация в AI-агентах

```bash
# Claude Desktop (автоопределение пути к конфигу в зависимости от платформы)
hesman install --agent claude

# Cursor
hesman install --agent cursor

# VS Code (с Copilot или Cline)
hesman install --agent vscode

# Используйте --global для записи в пользовательский конфиг вместо проектного
hesman install --agent claude --global
```

После установки перезапустите вашего AI-агента, и Hesman будет доступен как MCP-сервер.

### Ручная настройка MCP

Добавьте это в конфигурационный файл MCP вашего агента:

```json
{
  "mcpServers": {
    "hesman": {
      "command": "hesman",
      "args": ["--project-root", "/path/to/your/project"],
      "env": {}
    }
  }
}
```

## Справочник инструментов

Hesman предоставляет **11 инструментов** через MCP stdio-транспорт. Каждый ответ включает блок `_meta` с экономией токенов и, где применимо, блок `_summary`, агрегирующий результаты.

### Навигация по коду

| Инструмент | Что делает | Ключевые параметры |
|---|---|---|
| `find_symbol` | Поиск символов по имени с точным, нечётким или префиксным совпадением | `name`, `kind`, `matchMode`, `topK` |
| `get_file_structure` | Получение иерархического дерева всех символов в файле | `filePath`, `includeNested` |
| `get_references` | Поиск всех использований символа в кодовой базе | `symbolId`, `referenceKind`, `topK`, `cursor` |
| `get_context` | Получение сжатого кода вокруг указанного места | `filePath`, `startLine`, `contextLines`, `mode` |

### Граф вызовов

| Инструмент | Что делает | Ключевые параметры |
|---|---|---|
| `get_callers` | Поиск всех функций, которые вызывают данный символ (до 3 уровней глубины) | `symbolId`, `maxDepth`, `topK` |
| `get_callees` | Поиск всех функций, вызываемых данным символом (до 3 уровней глубины) | `symbolId`, `maxDepth`, `topK` |

### Анализ

| Инструмент | Что делает | Ключевые параметры |
|---|---|---|
| `impact_analysis` | Категоризация того, что сломается при изменении символа (переименование/удаление/изменение сигнатуры) | `symbolId`, `changeType` |
| `list_dependencies` | Показывает, что импортирует файл или что импортирует его | `filePath`, `direction` |
| `semantic_search` | Поиск кода по описанию на естественном языке | `query`, `topK`, `language`, `kind` |
| `find_pattern` | Поиск по структурному шаблону с именованными захватами (`$NAME`, `$$$ARGS`) | `pattern`, `language`, `topK` |

### Статус

| Инструмент | Что делает |
|---|---|
| `index_status` | Отчёт о состоянии индексации: количество файлов, количество символов, статус хранилищ, ожидающие файлы |

Полные схемы входных/выходных данных с примерами см. в **[docs/TOOLS.md](./docs/TOOLS.md)**.

## Конфигурация

Создайте `hesman.config.json` в корне вашего проекта (все поля опциональны):

```json
{
  "projectRoot": ".",
  "workers": 0,
  "watchMode": true,
  "languages": ["*"],
  "ignore": ["node_modules/**", "dist/**", ".git/**", "legacy/**"],
  "semanticSearch": {
    "enabled": true,
    "defaultTopK": 10,
    "maxTopK": 50,
    "embeddingModel": "Xenova/all-MiniLM-L6-v2"
  },
  "logLevel": "info",
  "dataDir": ".hesman"
}
```

### Приоритет конфигурации

Настройки разрешаются в следующем порядке (последующие переопределяют предыдущие):

1. **Значения по умолчанию** — встроены в Hesman
2. **`hesman.config.json`** — конфигурационный файл проекта
3. **Переменные окружения** — например, `HESMAN_WORKERS=4`
4. **Флаги CLI** — например, `--workers 4`

### Переменные окружения

| Переменная | Аналог в CLI | Описание |
|---|---|---|
| `HESMAN_PROJECT_ROOT` | `--project-root` | Путь к проекту для индексации |
| `HESMAN_WORKERS` | `--workers N` | Количество потоков-воркеров (0 = автоопределение) |
| `HESMAN_LOG_LEVEL` | `--log-level` | Одно из: trace, debug, info, warn, error |
| `HESMAN_DATA_DIR` | `--data-dir` | Директория для данных индекса (по умолчанию: `.hesman`) |
| `HESMAN_WATCH_MODE` | `--watch-mode` | Включение/отключение отслеживания файлов (true/false) |

### Флаги CLI

| Флаг | Описание |
|---|---|
| `--project-root <path>` | Корневая директория проекта |
| `--workers <N>` | Количество потоков-воркеров (0 = авто) |
| `--log-level <level>` | Уровень логирования |
| `--data-dir <path>` | Путь к директории данных |
| `--watch-mode` | Включить отслеживание файлов |
| `--no-watch` | Отключить отслеживание файлов |
| `--no-semantic` | Отключить семантический поиск |
| `--batch-size <N>` | Количество файлов в пакете индексации |

## Архитектура

```
                         ┌──────────────────────────────────────┐
                         │         AI Agent (Claude, etc.)       │
                         │              │  MCP stdio              │
                         └──────────────┼─────────────────────────┘
                                        │
                         ┌──────────────┼─────────────────────────┐
                         │       Hesman MCP Server                │
                         │              │                          │
                         │   ┌──────────┴──────────────────────┐  │
                         │   │     3-Layer Compression Pipeline │  │
                         │   │  ┌────────────────────────────┐  │  │
                         │   │  │ 1. Compact Mode            │  │  │
                         │   │  │    Strip comments/blanks    │  │  │
                         │   │  │ 2. Context Pruning         │  │  │
                         │   │  │    Keep only relevant lines │  │  │
                         │   │  │ 3. Smart Summarization     │  │  │
                         │   │  │    Aggregate & compress     │  │  │
                         │   │  └────────────────────────────┘  │  │
                         │   └───────────────────────────────────┘  │
                         │                                          │
                         │   ┌──────────┐ ┌──────────┐ ┌─────────┐ │
                         │   │  SQLite  │ │   ZVec   │ │ Worker  │ │
                         │   │  Store   │ │  Vector  │ │  Pool   │ │
                         │   │ (symbols)│ │ (search) │ │ (index) │ │
                         │   └────┬─────┘ └────┬─────┘ └────┬────┘ │
                         │        │            │            │       │
                         │   ┌────┴────────────┴────────────┴────┐  │
                         │   │     File Watcher (chokidar)       │  │
                         │   └───────────────────────────────────┘  │
                         └──────────────────────────────────────────┘
```

**Основной конвейер данных:** Изменения файлов (chokidar) -> Разбор Tree-sitter (AST + символы) -> Индекс SQLite + эмбеддинги ZVec -> Сжатые MCP-ответы

**Ключевые архитектурные решения:**
- **Без LSP** — Tree-sitter обеспечивает языконезависимый разбор без запуска языковых серверов
- **Инкрементальная индексация по хешу содержимого** — файлы переразбираются только при изменении SHA-256
- **Сжатие на уровне ответа** — исходные данные остаются нетронутыми; сжатие применяется на границе ответа
- **Единая SQLite-база на проект** — даже в монорепозиториях все пакеты используют одно хранилище с изоляцией через `file_path`

Полный документ архитектуры, включая зависимости модулей, схемы хранилищ и дизайн пула воркеров, см. в **[docs/ARCHITECTURE.md](./docs/ARCHITECTURE.md)**.

## Настройка окружения для разработки

### Предварительные требования

- **Node.js** ≥ 20.0.0
- **npm** ≥ 10

### Начало работы

```bash
# Клонирование и установка
git clone https://github.com/ocsen-hoc-code/hesman-mcp.git
cd hesman-mcp
npm install

# Загрузка WASM-парсеров Tree-sitter
npm run download:parsers

# Запуск в режиме разработки (горячая перезагрузка)
npm run dev

# Сборка для продакшена
npm run build
```

### Качество кода

```bash
npm run typecheck    # Проверка типов TypeScript
npm run lint         # ESLint
npm run format       # Форматирование Prettier
```

### Запуск тестов

```bash
npm test                  # Запуск всех тестов (модульные + интеграционные)
npm run test:watch        # Режим наблюдения для разработки
npm run test:e2e          # Сквозные тесты (запуск полного сервера)
npm run test:perf         # Бенчмарки производительности
```

### Целевые показатели производительности

| Бенчмарк | Цель |
|---|---|
| Пропускная способность индексации | ≥ 500 файлов/с |
| `find_symbol` (точный) | < 1 мс |
| `find_symbol` (нечёткий) | < 5 мс |
| `semantic_search` | < 10 мс |
| `get_references` | < 5 мс |
| Память (после индексации) | < 350 МБ |

Полное руководство для контрибьюторов, включая добавление новых языков, см. в **[docs/CONTRIBUTING.md](./docs/CONTRIBUTING.md)**.

## Требования

| Ресурс | Минимум |
|---|---|
| **Node.js** | ≥ 20.0.0 |
| **Память (простой)** | ~100 МБ |
| **Память (под нагрузкой)** | ~350 МБ |
| **Диск** | ~80 МБ (однократная загрузка модели эмбеддингов) |
| **Сеть** | Только для начального `npm install`; нулевые сетевые вызовы во время работы |

Модель эмбеддингов (`all-MiniLM-L6-v2`) загружается при первом использовании и бессрочно кешируется в директории кеша Transformers.js.
